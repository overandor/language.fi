Runtime
specification.

Canonical product boundary / version 0.1

Definition

A storage-rooted, proof-carrying runtime for persistent AI agents. The durable identity belongs to the capsule—not to a container, VM, process, cloud account, or physical computer.

Suspend a functioning agent into signed storage, destroy its original runtime, and restore it through the same SSH identity inside a newly materialized isolated environment—with its pending task, filesystem, permissions, and proof history intact.

Capsule contents

  • Stable agent identity, lineage epoch, and parent capsule hash
  • Model, tokenizer, runtime image, and policy content digests
  • Current objective, continuation point, and working summary
  • Content-addressed filesystem root
  • Capability grants, prohibitions, and secret references
  • Pending external-operation registry
  • Runtime compatibility manifest and restoration contract
  • Hash-linked execution and migration receipts
  • Cryptographic signature over the sealed manifest

Semantic quiescence

A seal is valid only when tool calls are complete or cancelled, files are flushed, transactions are closed, external effects have known commitment status, child processes are terminated or checkpointed, the next permitted action is recorded, and the receipt chain is finalized.

Restoration contracts

ContractMeaning
ExactArchitecture, runtime, process representation, and relevant hardware are compatible.
SemanticThe operational task is reconstructed from a portable checkpoint without claiming bit-identical continuation.
DegradedA required tool, model, route, or accelerator is unavailable and the limitation is explicitly accepted.

Capability invariant

Authority may be preserved or reduced, but it must never silently increase.

Providers translate abstract capabilities into filesystem mounts, network policy, executable allowlists, API scopes, secret-broker grants, spending ceilings, resource limits, approval requirements, and delegation depth.

Stable identity flow

ssh agent-id@runtime-network
→ authenticate caller
→ resolve latest authorized capsule
→ acquire exclusive wake lease
→ reject rollback, corruption, or unauthorized forks
→ materialize isolated runtime
→ restore and verify capabilities
→ attach stream
→ seal and collapse after inactivity

Proof boundary

Receipts prove observable transitions: the requesting capsule, evaluated policy, authorizing capability, runtime image, operation, committed inputs, observed outputs, changed resources, verification result, preceding receipt, and resulting capsule. A signature proves integrity and attribution—not intelligent intent.

Explicitly out of scope

  • Exact Metal-to-CUDA continuation
  • Cross-ISA register translation
  • Live restoration of arbitrary GPU kernels
  • Preservation of every active TCP session
  • Deterministic replay across unrelated model providers
  • A universal compute marketplace
